# Reviewed two-file Codex comparison

This milestone extends the existing restricted Codex CLI adapter without adding model tools or changing single-file analysis. Select two different regular files from the same evidence and recorded filesystem analysis, then open **Compare with Codex**. Each complete file must be valid UTF-8 and at most 1 MiB. Preparation freshly extracts and independently verifies complete bytes using the existing engine/private scratch service; it does not send a provider request.

Choose ordered, disjoint zero-based half-open **UTF-8 byte ranges** (for example `0:120,150:180`) and optional redaction ranges. Boundaries may not split a Unicode scalar. Redactions are subtracted before disclosure; hidden text is not reintroduced in a saved context. **Apply Ranges / Redactions** builds explicit surviving segments such as `A1`, `A2`, `B1`. Each segment records its original byte range and disclosed SHA-256, so citations do not silently shift after redaction. Empty/omitted coverage remains explicit. Excerpts are limited to 32 KiB per file / 64 KiB combined, at most 32 selected and 32 redacted intervals per file, and 64 surviving segments per file. A separate 192 KiB serialized request cap covers JSON escaping, question, metadata and follow-up context.

Open **Exact Payload**, review the exact app-to-CLI UTF-8 request, check the disclosure agreement, and press **Send to Codex**. The store compares the confirmed bytes with the current payload and rehashes ordered source containers before invoking the existing isolated CLI adapter. Changes to question, ranges, parent or selection require a new review. The provider sees only that reviewed request, not the disk image or host source paths. Network/account usage happens only after Send. Preview, redaction, history, Save and citation opening never invoke the provider.

The model is asked to cite inline markers `[[A1:0:5]]`, where offsets are UTF-8 bytes within that disclosed segment. The app validates marker IDs, bounds and Unicode boundaries against the exact request. Unknown/fabricated/out-of-range references appear unresolved; resolving a range does **not** validate the model's factual interpretation or attribution. **Open Verified Bytes** freshly extracts the selected files again and requires the original case/evidence/snapshot/entry binding and complete-file SHA-256 before displaying cited text. Changed, unavailable or mismatched content cannot be opened as current evidence. Response text is literal, not actionable model markup or links.

**Save Comparison** is an explicit local action after the completed result's request hash is verified. Immutable schema-v1 receipts are stored under `.nativecase/comparisons/<uuid>.json`, with both complete bindings, transformation/range maps, hashes, coverage, warnings, resolved/unresolved citations, question and structured AI answer. Full retention stores the exact reviewed prompt including disclosed text; digest-only removes prompt and segment text, retaining hashes/range metadata and the answer/question, which may themselves quote evidence. The UI states this choice. No raw provider log, credential, host source path or unredacted complete file is automatically retained. Each serialized record is capped at 1 MiB, with no silent truncation; history scans one bounded record at a time and retains at most 50 small summaries per page; Newest/Load Older navigation keeps old receipts reachable without accumulating all history in memory. Saved answers display their original question and file pair. Records are historical receipts and can be read offline without rehashing evidence.

Select **Reviewed Follow-up** after saving/opening a compatible parent. The new request includes the saved parent ID and its previous answer labeled as untrusted interpretation; changing any selected/redacted ranges clears the parent, and Core requires the same disclosure map as the saved parent so a prior answer cannot bypass a newly changed redaction; it has its own exact review, limits, source check and request hash. The immutable child binds both parent ID and parent request hash, and publication requires the corresponding saved parent in the same case/evidence/snapshot. A prior answer never acquires tool access or becomes a deterministic fact.

Case publication holds the existing case lock, pins no-follow directory/manifest/lock descriptors, writes mode-0600 private staging, flushes it, validates current identities and atomically publishes without replacement. Duplicate UUIDs, symlink replacements, malformed records and missing/wrong parents are refused. Cancellation/close drains the owning task and helper cleanup before the sheet is reused; a late cancellation after atomic publication keeps the committed receipt. The native default save moves blocking lock/write/fsync work to the shared blocking queue with an explicit cancellation token.

Current scope: two UTF-8 filesystem entries from one evidence and recorded snapshot. PDF/decoder references, multi-evidence joins, case-wide retrieval, AI factual verification and live provider benchmark are separate gates. Automated tests use synthetic files and fake provider responses only; a synthetic integration probe may exercise real extraction but does not contact a provider. Local fake-provider validation is not proof of account login or a returned live model answer.
