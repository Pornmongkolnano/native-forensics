# Timeline and report implementation scope

Timeline implementation now combines one selected recorded filesystem listing, one explicitly selected allocated Chromium History artifact set, and one explicitly selected allocated UTF-8 syslog file. The complete report exports deterministic observations separately from examiner notes and an optional explicitly supplied AI interpretation. Native export supplies no AI interpretation and no parser asks AI to create events.

This closes the previously missing implementation paths for bounded syslog import and native PDF output. It does not close the entire roadmap, every artifact parser family, Autopsy parity, distribution trust, APFS/FileVault, physical M5, or full unallocated/deleted-record coverage. A successful 19-event workflow fixture would only establish that fixture's observed behavior.

## Syslog input and provenance

`FilesystemSyslogTimelineService` selects the exact file from its evidence/listing binding, rejects deleted/directory/oversized entries, freshly verifies ordered evidence sources through the extraction engine, claims the extracted scratch descriptor, and verifies the complete extracted bytes against their size/SHA-256 receipt before parsing. It checks all source containers again after parsing and removes only its owned scratch. Source images and source files are never written.

The selected raw text path is `raw-utf8.v1`, limited to 1 MiB strict UTF-8, 16 KiB per source line and 20,000 observations. It preserves extracted bytes as derived text: extracted-content SHA-256 and derived-text SHA-256 therefore match. An optional initial UTF-8 BOM is ignored only for recognizing the first timestamp; it remains in the byte digest/range. References identify document unit 1, one-based line, UTF-8 offset and length; no PDF page or original document-layout page is invented. Source URL/scratch URL is runtime-only.

Newline policy is exact: source lines split at LF. The raw `sourceReference` span starts at the original line byte offset and excludes the delimiting LF, while retaining a preceding CR. `event.detail` presents line content and removes exactly one terminal CR before timestamp parsing/display, including a terminal CR at EOF; it does not strip embedded CR characters. For a CRLF line, the referenced bytes therefore end in CR while the detail string does not. These are different representations, not a source-byte/hash failure. The complete source/derived digest still includes every original CR and LF; no source newline normalization occurs. Use the raw reference for exact bytes rather than reconstructing them from `detail`.

Recognized prefixes are classic RFC3164 civil time, RFC3339 with an explicit offset, and an RFC5424 priority/version-1 prefix followed by RFC3339. Unsupported or nonempty unrecognized lines and invalid timestamps are counted explicitly in the parser receipt. They create no guessed event. The report preserves the recorded line-content detail together with its exact raw source reference and does not assert that a named person performed an action or that a message is true.

Classic syslog requires an explicit year from 1970 through 9999 and an IANA timezone. The selected year applies independently to every classic line; there is no current-year or rollover inference. `preserveUnresolved` keeps both DST-overlap candidates and leaves gaps without an instant; `rejectAmbiguousOrNonexistent` rejects the entire import. A host timezone is never substituted. RFC3339 `-00:00` remains unknown-offset, fractions retain up to nine digits, and leap seconds/out-of-bounds UTC instants remain invalid. Parsing bounds are UTC years 1970 through 9999.

The native picker shows up to 1,000 eligible recorded files, with conventional log names first, and displays shown/eligible counts. Byte validation determines whether the selected file is UTF-8; a filename does not prove log format. Each new log import replaces the earlier log import and retains the selected Chromium observations from the same snapshot. Chromium imports similarly replace their own family and retain syslog observations. A new listing/evidence selection invalidates the prior view; canceled or stale completions cannot reopen it.

## Filesystem timestamp interpretation

When the engine supplies `FilesystemCivilTimestamp`, each event retains raw date/time/increment/offset fields, civil spelling, native precision, selected IANA zone or recorded offset, interpretation and candidate epochs. Gap/overlap/invalid-calendar observations remain present even with no singular epoch. A missing raw field creates no event. Legacy entries without provenance keep the existing normalized engine values and explicitly state unavailable original civil spelling/offset/precision. Metadata is a recorded snapshot; building this timeline does not refresh source bytes or invent a deletion time.

## Reconstructible report binding

New report bindings retain engine protocol schema, engine/patch identity, complete selected `EngineOptions`, sanitized image parameters, volume geometry, and every selected container in recorded ordinal order with byte count when retained by the original listing, SHA-256 and `selected-file-bytes` scope. Logical/decompressed image hashes and extracted-artifact hashes have separate scopes. The snapshot digest remains an identity check, not a substitute for these readable parameters. Parser receipts record component versions, selected parameters, caps, source/derived hashes, unit/line/event counts and rejected-line coverage.

Report schema 1 and historical `timeline.v1` JSON remain decodable without rewriting. New reports use `timeline.v2` and filesystem parser `filesystem-engine-epochs.v2`; added provenance is optional for historical decoding. Missing historical options, source sizes, raw civil fields or parser parameters are labelled unavailable, never reconstructed from the digest.

## Native PDF and exclusive export

`TimelinePDFRenderer` uses CoreGraphics/CoreText to draw static text, with font fallback for Thai and bounded wrapping for long paths, long unbroken tokens and whitespace. It embeds no URL actions, annotations, JavaScript, original document data, or executable objects. It prints all events in report order, event IDs, file/record/source pointers, raw/normalized timestamps, alternatives, precision, time assumptions, every source/artifact/parser receipt, coverage/warnings, examiner notes and a separate unverified AI section. Invisible control bytes are printed as escaped markers rather than disappearing.

PDF pagination is bounded to 10,000 pages and output to 64 MiB. JSON and Markdown each retain the 64 MiB output bound; notes/AI text each retain 32 KiB. A page/byte/time/cancel failure rejects the complete publication; there is no silently dropped report tail. The export contains the whole timeline regardless of presentation filters.

`timeline.json`, `timeline.md`, `timeline.pdf` and `receipt.json` publish together into a new directory. Owned descriptors use exclusive/no-follow creation, fsync, independent written-byte rehash and exclusive directory rename. Existing outputs, evidence/case-overlapping destinations and symlink/alias destinations are rejected. The shareable receipt records hashes of all three reports and contains no runtime destination or scratch path. Runtime receipt destination supports Show Reports only.

## Verification evidence and open gates

The renderer's latest standalone synthetic Swift 6 probe produced a 27-page 205,615-byte long report and a four-page 42,412-byte full-provenance report. PDFKit and Poppler read back all 24 event/record/path/detail tails, all 2,160 Thai tokens, examiner/AI tails and the engine/parser/source/native timestamp fields; catalog/page checks found no annotations/actions. Reduced 128-byte and one-page limits failed closed. Raster inspection of all four provenance pages, a 27-page contact sheet, and individual Thai/long-path/final-AI pages found no overlap or clipping. PDF text extraction normalizes layout whitespace, so token-based readback is separate from raw UTF-8 byte checks. These are renderer observations, not filesystem extraction or provider evidence.

Added source tests include independent fixed UTF-8 SHA-256, exact epoch/nanosecond constants, CRLF offsets and line ranges, DST overlap/gap policies, unknown RFC3339 offsets, invalid calendars/UTC bounds, byte/line/event caps, invalid UTF-8/binary input, changed/symlink bytes, historical-v1 decoding, native timestamp uncertainty, report pointer bounds, report hashes and native canceled/stale/import-family lifecycle behavior. Root-run SwiftPM and actual helper/GUI results must be read from the current validation receipts; test presence alone is not a passed execution.

Open coverage includes non-UTF-8 logs, RFC5424 variants beyond the supported prefix, multiline log record semantics, automatic year rollover, multiple simultaneous log/database artifacts, deleted syslog recovery, case-wide artifact scanning, additional browser families, SQLite deleted/free pages, and broad timestamp/format differential fixtures. Invalid/unrecognized lines and bounded picker coverage must remain visible when using the report.
